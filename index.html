Next-Concept Modeling

A language model that writes in levels: a rough sketch of the whole passage first, then finer and finer detail, with every piece of a level written at once.

Three ways to write 16 tokens

Each wall shows one model writing the same 16-token sentence. Read it top to bottom: one row is one forward pass through the network, and each cube is a position the model works on in that pass.

  • Next-token (GPT-style). Writes one token per pass, reading everything before it (the faint cubes). 16 tokens take 16 passes.
  • Masked diffusion. Every pass looks at all 16 positions and commits one more token (grey cubes are still masked). The paper's baselines use as many passes as tokens; cutting passes hurts quality.
  • Next-Concept Modeling. 5 passes. Pass 1 predicts one code for the whole passage, pass 2 predicts two, then 4, 8 and 16. Each pass fills its whole row at once.

At real scale, a 128-token LM1B sample takes NCM 12 passes against 128 for the diffusion baselines. This sketch doubles the level size each time; the paper tests several size schedules.

Step 1: squeeze the text into levels of codes

Before any generating, a tokenizer (a multiscale residual VQ-VAE) learns to describe a passage as a stack of discrete codes.

  1. The encoder turns each token into a latent vector. Here each one is drawn as a single bar; in the paper it has 384 numbers.
  2. Level 1 summarizes the whole passage with one code, picked from a learned codebook of 4,096 to 8,192 entries.
  3. Each next level uses more codes to describe what is still wrong (the residual) and adds its correction.
  4. With every level in place, the decoder recovers the original tokens: 99.99% of them on OpenWebText.

Training sometimes drops the later levels (nested dropout), so the first few levels learn to carry the big picture on their own. Drag the slider to see how much each level adds.

Step 2: generate the levels, coarse to fine

A transformer builds the code stack from the top down. Each pass fills one whole level.

  1. Pass k gets the running reconstruction from the levels above, resized to the number of slots in level k (the outlines).
  2. It predicts every code in that level in parallel.
  3. After the last level, the tokenizer's decoder turns the stack into words.
Attention mask: slots in a level attend only to each other. Everything from earlier levels arrives through the input instead.
Decoded outputThe old lighthouse keeper climbed the spiral stairs every night to light the lamp.

The number of passes equals the number of levels, not the length of the text: 12 for 128 tokens (LM1B), 32 for 1,024 tokens (OpenWebText). The coarse levels are not readable drafts; the paper treats them as a plan.

Caveats

  • Tested on small models only (largest: 725M parameters).
  • The tokenizer is trained first, then frozen.
  • Every input gets the same number of levels, easy or hard.
  • Tokenizer slips can garble exact names and numbers.
  • Speedups depend on the hardware and timing setup.
